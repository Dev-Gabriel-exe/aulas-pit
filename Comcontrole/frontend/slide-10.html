Client-side ML — tensores, backends e quando usar
Server-side vs Client-side ML

Nas semanas anteriores, toda a inteligência estava no servidor — você enviava texto para a API da OpenAI e recebia uma resposta. Com TensorFlow.js, o modelo roda dentro do browser do usuário, usando a CPU ou GPU local. Isso muda completamente o modelo de custo, privacidade e latência.

Server-side (API OpenAI, semanas 5–8)
Modelos enormes (GPT-4 tem ~1.8T parâmetros)
Zero setup no cliente — só uma requisição fetch
Sempre atualizado — você não gerencia o modelo
Latência de rede para cada predição
Custo por token/requisição
Dados saem do dispositivo do usuário
Offline = não funciona
Client-side (TF.js — hoje)
Predição em ~10–100ms — sem latência de rede
Dados ficam no dispositivo — privacidade real
Funciona offline após carregar o modelo
Sem custo por inferência após download do modelo
Modelos grandes demais para o browser (limite ~500MB)
GPU do usuário é imprevisível (mobile vs desktop)
Modelo fica exposto — qualquer um pode extrair os pesos
Download inicial do modelo (MobileNet ~16MB)
Quando usar client-side ML: dados sensíveis que não podem sair do dispositivo (foto do rosto, áudio, documentos privados), aplicações que precisam funcionar offline, casos onde latência mínima é crítica (detecção em tempo real via câmera), e modelos compactos suficientes para a tarefa (classificação de imagem, detecção de objetos simples).
Tensores — a estrutura de dados do TF.js

Tudo no TensorFlow.js é um tensor — um array multidimensional tipado. Um número é um tensor de rank 0, um vetor é rank 1, uma imagem colorida 224×224 é um tensor de rank 3 com shape [224, 224, 3].

A diferença crítica entre tensores e arrays JavaScript: tensores vivem na memória da GPU (WebGL), têm tipo fixo (float32, int32…) e precisam ser descartados manualmente com .dispose() para evitar memory leaks.

Shapes de tensor mais comuns em visão computacional
Pixel único RGB → [3] // [R, G, B] — rank 1
Imagem 224×224 → [224, 224, 3] // height, width, channels — rank 3
Batch de 8 imagens → [8, 224, 224, 3] // batch, h, w, c — rank 4
Saída MobileNet → [1, 1000] // batch=1, 1000 classes ImageNet
Classe predita → [1] // índice do argmax
JavaScript — operações básicas com tensores
import * as tf from '@tensorflow/tfjs';

// Criando tensores
const escalar = tf.scalar(3.14);           // shape: []
const vetor   = tf.tensor1d([1, 2, 3]);   // shape: [3]
const matriz  = tf.tensor2d([[1,2],[3,4]]); // shape: [2, 2]

// Inspecionando
vetor.print();           // Tensor [1, 2, 3]
console.log(vetor.shape); // [3]
console.log(vetor.dtype); // 'float32'

// Convertendo de volta para JS (assíncrono)
const jsArray = await vetor.array();  // [1, 2, 3]
const jsData  = await vetor.data();   // Float32Array([1, 2, 3])

// ⚠ SEMPRE descartar tensores que não serão mais usados
vetor.dispose();
// Ou usar tf.tidy() para limpar automaticamente:
const resultado = tf.tidy(() => {
  const a = tf.tensor1d([1, 2, 3]);
  const b = tf.tensor1d([4, 5, 6]);
  return a.add(b); // a e b são descartados, resultado é retornado
});
// resultado ainda existe; descarte quando terminar:
resultado.dispose();
Memory leak com tensores: cada tensor criado ocupa memória GPU. Se você criar tensores dentro de funções chamadas repetidamente (ex: a cada frame de vídeo) sem .dispose() ou tf.tidy(), a memória GPU esgota em minutos e o browser trava. Use tf.memory().numTensors no console para monitorar.
🙋 Por que tensores no TensorFlow.js precisam ser descartados com .dispose() enquanto objetos JavaScript normais não precisam?
A
É uma convenção da API — tecnicamente o garbage collector do browser já cuidaria, mas .dispose() é mais explícito
B
Tensores vivem na memória da GPU (WebGL), fora do controle do garbage collector do JavaScript — o GC não consegue liberar essa memória automaticamente
C
.dispose() apenas marca o tensor como inativo — a memória só é liberada quando o browser reinicia
D
Tensores não têm garbage collector porque são imutáveis — .dispose() é necessário por segurança de dados

React — hook para carregar modelo uma vez
import { useState, useEffect } from 'react';
import * as mobilenet from '@tensorflow-models/mobilenet';
import '@tensorflow/tfjs';  // necessário para o backend WebGL

export function useModelo() {
  const [modelo, setModelo] = useState(null);
  const [carregando, setCarregando] = useState(true);
  const [erro, setErro] = useState(null);

  useEffect(() => {
    let cancelado = false;

    async function carregar() {
      try {
        // MobileNet faz o download dos pesos (~16MB) na primeira chamada
        // O browser faz cache — carregamentos seguintes são instantâneos
        const m = await mobilenet.load({ version: 2, alpha: 1.0 });
        if (!cancelado) setModelo(m);
      } catch (e) {
        if (!cancelado) setErro(e.message);
      } finally {
        if (!cancelado) setCarregando(false);
      }
    }

    carregar();
    return () => { cancelado = true; };  // cleanup se componente desmontar
  }, []);

  return { modelo, carregando, erro };
}
version: 2, alpha: 1.0 — alpha controla a largura do modelo: 0.25 é mais leve (menos acurado), 1.0 é o modelo completo. Para mobile, alpha 0.5 oferece bom equilíbrio. O modelo v2 é mais preciso que v1 para a maioria das classes.

JavaScript — pipeline completo de pré-processamento + predição
import * as tf from '@tensorflow/tfjs';

/**
 * Carrega um arquivo de imagem e retorna um DataURL
 */
function lerArquivoComoURL(arquivo) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload  = (e) => resolve(e.target.result);
    reader.onerror = () => reject(new Error('Erro ao ler arquivo'));
    reader.readAsDataURL(arquivo);
  });
}

/**
 * Cria um HTMLImageElement a partir de uma URL (DataURL ou http)
 */
function carregarImagem(url) {
  return new Promise((resolve, reject) => {
    const img = new Image();
    img.onload  = () => resolve(img);
    img.onerror = () => reject(new Error('Falha ao carregar imagem'));
    img.src = url;
  });
}

/**
 * Pré-processa HTMLImageElement → tensor [1, 224, 224, 3] normalizado
 * Todos os tensores intermediários são descartados pelo tf.tidy()
 */
function preprocessar(imgElement) {
  return tf.tidy(() => {
    return tf.image
      .resizeBilinear(
        tf.browser.fromPixels(imgElement),  // [h, w, 3] uint8
        [224, 224]                            // redimensiona para [224, 224, 3]
      )
      .toFloat()                             // converte para float32
      .div(tf.scalar(127.5))                 // normaliza para [0, 2]
      .sub(tf.scalar(1))                      // desloca para [-1, 1]
      .expandDims(0);                         // adiciona batch: [1, 224, 224, 3]
  });
}

/**
 * Função principal: arquivo → top-5 predições
 */
async function classificar(arquivo, modelo) {
  const url   = await lerArquivoComoURL(arquivo);
  const img   = await carregarImagem(url);

  // O pacote mobilenet já expõe classify() que faz tudo isso por você:
  const preds = await modelo.classify(img, 5);  // top-5
  // preds: [{className: 'cat', probability: 0.94}, ...]
  return { url, preds };
}

// OU usando model.predict() diretamente (para modelos customizados):
async function classificarManual(arquivo, modelo, classes) {
  const url     = await lerArquivoComoURL(arquivo);
  const img     = await carregarImagem(url);
  const tensor  = preprocessar(img);

  const saida   = modelo.predict(tensor);   // [1, n_classes]
  const probs   = await saida.data();        // Float32Array com probabilidades
  const topIdx  = Array.from(probs)
    .map((p, i) => ({ p, i }))
    .sort((a, b) => b.p - a.p)
    .slice(0, 5)
    .map(({ p, i }) => ({ classe: classes[i], prob: p }));

  tensor.dispose();
  saida.dispose();
  return { url, topIdx };
}
🙋 O MobileNet espera imagens com valores entre -1 e 1. Uma imagem JPEG vem com valores entre 0 e 255. Qual sequência de operações normaliza corretamente?
A
dividir por 255 → subtrair 0.5 → multiplicar por 2
B
dividir por 127.5 → subtrair 1     (equivalente a: valor → valor/127.5 - 1)
C
subtrair 128 → dividir por 128
D
dividir por 255 apenas — o MobileNet trata o resto internamente

React — ClassificadorImagem.jsx completo
import { useState, useRef, useCallback } from 'react';
import * as tf from '@tensorflow/tfjs';
import { useModelo } from './useModelo';
import './ClassificadorImagem.css';

export default function ClassificadorImagem() {
  const { modelo, carregando } = useModelo();
  const [imgUrl, setImgUrl] = useState(null);
  const [predicoes, setPredicoes] = useState([]);
  const [classificando, setClassificando] = useState(false);
  const [stats, setStats] = useState(null);
  const imgRef = useRef(null);

  const classificar = useCallback(async () => {
    if (!modelo || !imgRef.current) return;
    setClassificando(true);
    try {
      const inicio = performance.now();
      const preds = await modelo.classify(imgRef.current, 5);
      const tempo = (performance.now() - inicio).toFixed(0);
      setPredicoes(preds);
      setStats({
        tempo,
        backend: tf.getBackend(),
        tensores: tf.memory().numTensors,
      });
    } finally {
      setClassificando(false);
    }
  }, [modelo]);

  function aoSelecionarArquivo(e) {
    const arquivo = e.target.files[0];
    if (!arquivo) return;
    setPredicoes([]);
    setStats(null);
    const reader = new FileReader();
    reader.onload = (ev) => setImgUrl(ev.target.result);
    reader.readAsDataURL(arquivo);
  }

  if (carregando) return (
    <div className="cls-loading">
      <div className="cls-spinner" />
      <p>Carregando MobileNet (~16 MB)...</p>
    </div>
  );

  return (
    <div className="cls">
      <h1 className="cls-titulo">Classificador de Imagem</h1>
      <p className="cls-sub">MobileNet v2 · 1000 classes · 100% no browser</p>

      <label className="cls-upload">
        {imgUrl
          ? <img ref={imgRef} src={imgUrl} alt="preview" className="cls-preview"
              onLoad={classificar} />
          : <div className="cls-placeholder">
              <i className="fas fa-cloud-upload-alt"></i>
              <p>Clique ou arraste uma imagem aqui</p>
            </div>
        }
        <input type="file" accept="image/*" onChange={aoSelecionarArquivo} hidden />
      </label>

      {classificando && <p className="cls-status">⏳ Classificando...</p>}

      {predicoes.length > 0 && (
        <div className="cls-resultado">
          {predicoes.map((p) => (
            <div key={p.className} className="cls-pred-row">
              <span className="cls-pred-label">{p.className}</span>
              <div className="cls-pred-track">
                <div
                  className="cls-pred-fill"
                  style={{ width: `${(p.probability * 100).toFixed(1)}%` }}
                />
              </div>
              <span className="cls-pred-pct">
                {(p.probability * 100).toFixed(1)}%
              </span>
            </div>
          ))}
          {stats && (
            <div className="cls-stats">
              {stats.tempo}ms · {stats.backend} · {stats.tensores} tensores
            </div>
          )}
        </div>
      )}
    </div>
  );
}

Exercício 01 — Monitorando memória

Adicione ao classificador um botão "Classificar novamente" que chama modelo.classify() sem recarregar a imagem. Classifique a mesma imagem 10 vezes e observe o valor de tf.memory().numTensors a cada chamada. O número cresce? Se sim, por que? Se não, como o MobileNet garante isso? Documente sua observação.

Observação
  • O número de tensores NÃO deve crescer a cada classificação — se crescer, há um leak. O pacote @tensorflow-models/mobilenet usa tf.tidy() internamente para limpar tensores intermediários, retornando apenas o resultado final.
  • Os tensores ativos após carregar o modelo são os pesos do modelo — esses ficam na memória para sempre (necessário para inferência rápida). O número que você vê é constante, não cresce com cada predição.
  • Para verificar: const antes = tf.memory().numTensors; await modelo.classify(img); const depois = tf.memory().numTensors; console.log(depois - antes); deve imprimir 0.
Exercício 02 — Classificação via câmera em tempo real

Substitua o input de arquivo por um feed de câmera ao vivo usando navigator.mediaDevices.getUserMedia(). Classifique o frame atual a cada 500ms usando setInterval. Passe o elemento <video> diretamente para modelo.classify(videoRef.current) — o TF.js aceita HTMLVideoElement como entrada. Não esqueça de parar a câmera e limpar o interval no cleanup do useEffect.

React — trecho da câmera em tempo real
const videoRef = useRef(null);

useEffect(() => {
  let stream, intervalId;

  async function iniciarCamera() {
    stream = await navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } });
    videoRef.current.srcObject = stream;
    await videoRef.current.play();

    intervalId = setInterval(async () => {
      if (!modelo || !videoRef.current) return;
      const preds = await modelo.classify(videoRef.current, 3);
      setPredicoes(preds);
    }, 500);
  }

  if (modelo) iniciarCamera();

  return () => {
    clearInterval(intervalId);
    stream?.getTracks().forEach(t => t.stop());
  };
}, [modelo]);

const modelo = await tf.loadLayersModel('/modelo_tfjs/model.json');

// Se treinou com imagens divididas por 255.0 em Python:
const tensor = tf.tidy(() =>
  tf.browser.fromPixels(img)
    .toFloat()
    .div(tf.scalar(255.0))   // deve ser EXATAMENTE o mesmo que no treino
    .expandDims(0)

const prob  = (await saida.data())[0];
console.log(`Probabilidade classe 1: ${(prob*100).toFixed(1)}%`);
Por que o pré-processamento precisa ser idêntico

O modelo aprendeu padrões nos dados na escala em que foram apresentados. Se treinou com pixels entre 0 e 1 (÷255) e você inferir com pixels entre -1 e 1 (÷127.5 − 1), os pesos que aprenderam "gato tem padrão X em escala [0,1]" receberão entrada em escala diferente e as ativações serão completamente diferentes. A predição será aleatória, não importa quão bem o modelo foi treinado.

O que você precisa ter saído daqui dominando
Tensores e memória

Tensor = array multidimensional na GPU. Shape define as dimensões. Sempre usar tf.tidy() ou .dispose() para evitar memory leak. tf.memory().numTensors para monitorar.

Pipeline de pré-processamento

Arquivo → FileReader → DataURL → HTMLImageElement → tf.browser.fromPixels → resize → normalizar → expandDims. Normalização DEVE ser idêntica ao treino.

Inferência client-side

mobilenet.load() uma vez no useEffect. classify(imgElement, topK) retorna array de {className, probability}. Modelo fica no browser — zero latência de rede, zero custo por predição.

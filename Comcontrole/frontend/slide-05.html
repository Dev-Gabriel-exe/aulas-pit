Gratuito (limites)
O padrão que todos seguem: mensagens são um array de objetos {"{"}role, content{"}"}. Role pode ser system (instrução para o modelo), user (mensagem do usuário) ou assistant (resposta do modelo). A OpenAI popularizou esse formato — Gemini e outros o adotaram.

O histórico é responsabilidade sua. A API de chat não tem memória entre chamadas. Para manter contexto, você manda o histórico completo a cada requisição — é por isso que o array de mensagens cresce com cada turno da conversa.
Hook useChat — o coração do chatbot real
JSX — hooks/useChat.js
import { useState } from 'react';

const SYSTEM_PROMPT_PADRAO =
  'Você é um assistente de front-end para IA. Responda em português, de forma didática e objetiva.';

export function useChat({
  modelo       = 'gpt-4o-mini',
  systemPrompt = SYSTEM_PROMPT_PADRAO,
  maxTokens    = 1000,
} = {}) {
  const [historico,   setHistorico]   = useState([]); // {role, content}[]
  const [carregando,  setCarregando]  = useState(false);
  const [erro,        setErro]        = useState(null);
  const [totalTokens, setTotalTokens] = useState(0);

  const enviar = async (textoUsuario) => {
    if (!textoUsuario.trim() || carregando) return;

    // 1. Adiciona mensagem do usuário ao histórico
    const msgUsuario = { role: 'user', content: textoUsuario };
    const historicoAtualizado = [...historico, msgUsuario];
    setHistorico(historicoAtualizado);
    setCarregando(true);
    setErro(null);

    try {
      const res = await fetch('https://api.openai.com/v1/chat/completions', {
        method:  'POST',
        headers: {
          'Content-Type':  'application/json',
          'Authorization': `Bearer ${import.meta.env.VITE_OPENAI_KEY}`,
        },
        body: JSON.stringify({
          model:      modelo,
          max_tokens: maxTokens,
          messages: [
            { role: 'system', content: systemPrompt }, // system sempre primeiro
            ...historicoAtualizado,                         // histórico completo
          ],
        }),
      });

      if (!res.ok) {
        const errJson = await res.json().catch(() => ({}));
        throw new Error(errJson.error?.message || `Erro ${res.status}`);
      }

      const data = await res.json();
      const msgIA = data.choices[0].message; // { role:'assistant', content:'...' }

      // 2. Adiciona resposta da IA ao histórico
      setHistorico(h => [...h, msgIA]);
      setTotalTokens(t => t + (data.usage?.total_tokens || 0));

    } catch (e) {
      setErro(e.message);
    } finally {
      setCarregando(false);
    }
  };

  const limpar = () => { setHistorico([]); setErro(null); setTotalTokens(0); };

  return { historico, carregando, erro, totalTokens, enviar, limpar };
}

Tokens — a moeda das APIs de IA

Modelos de linguagem não processam palavras — processam tokens. Um token é, em média, 4 caracteres ou ¾ de uma palavra em inglês. Em português, textos tendem a usar mais tokens que em inglês.

ExemploTokens aprox.Observação
"Olá, tudo bem?"~6Frases curtas = poucos tokens
Uma página de texto~500Regra: 750 palavras ≈ 1000 tokens
Um system prompt detalhado~200–500Vai em cada requisição — cuidado com custo
Histórico de 20 turnos~3000–8000Cresce a cada mensagem — gerenciar contexto
Context window GPT-4o128.000Limite máximo por requisição
Modelogpt-4o-mini
Input (prompt + histórico)$0.15 / 1M tokens
Output (resposta)$0.60 / 1M tokens
1000 conversas de ~2k tokens≈ $0.30
Estimativa mensal (app pequeno)$1 – $10
Gestão de contexto: quando o histórico fica longo, é comum truncar as mensagens mais antigas, manter só as últimas N, ou resumir a conversa anterior com uma chamada extra à API. Isso evita estourar o context window e reduz custos.
Rate limits — o que fazer quando a API rejeita

Todo provedor limita quantas requisições você pode fazer por minuto/dia. Erros 429 Too Many Requests são normais — a estratégia é tratá-los com elegância.

Requisições/min
3/5 rpm
Tokens/min
70k/200k
Tokens/dia
800k/10M
JavaScript — retry com backoff exponencial
// Tenta novamente em caso de 429, com espera crescente
async function fetchComRetry(url, opcoes, tentativas = 3) {
  for (let i = 0; i < tentativas; i++) {
    const res = await fetch(url, opcoes);

    if (res.status === 429) {
      const espera = Math.pow(2, i) * 1000; // 1s, 2s, 4s
      console.warn(`Rate limit. Tentativa ${i+1}. Aguardando ${espera}ms...`);
      await new Promise(r => setTimeout(r, espera));
      continue;
    }

    if (!res.ok) throw new Error(`Erro ${res.status}`);
    return res.json();
  }
  throw new Error('Limite de tentativas atingido. Tente novamente em alguns segundos.');
}

// No componente React — tratar 429 com mensagem amigável
catch (e) {
  if (e.message.includes('429')) {
    setErro('Muitas requisições. Aguarde alguns segundos e tente novamente.');
  } else if (e.message.includes('401')) {
    setErro('Chave de API inválida. Verifique suas configurações.');
  } else {
    setErro(`Erro: ${e.message}`);
  }
}

Segurança — o que o .env não resolve

Na Semana 4 aprendemos que .env protege a chave do git. Mas o .env não protege do usuário final — qualquer pessoa pode abrir o DevTools e ver a chave no cabeçalho da requisição.

    },

  });

  const data = await res.json();
  return Response.json(data);
}

Interface completa com histórico, system prompt editável e contador de tokens. O código abaixo é o componente que você vai construir:

Olá! Sou a demo da Semana 5. Nesta versão estou simulando respostas — na sua implementação real, conecte ao hook useChat com sua chave de API. 🚀

JSX — ChatbotIA.jsx — componente completo
import { useState, useRef, useEffect } from 'react';
import { useChat } from '../hooks/useChat';

const SYSTEM_PROMPTS = {
  assistente: 'Você é um assistente didático de front-end para IA. Responda em português, de forma clara e com exemplos de código quando relevante.',
  revisor:    'Você é um revisor de código React experiente. Ao receber código, aponte melhorias, bugs potenciais e melhores práticas.',
  tutor:      'Você é um tutor socrático. Em vez de dar respostas diretas, faça perguntas que levem o aluno a descobrir a resposta.',
};

export default function ChatbotIA() {
  const [modoSP, setModoSP] = useState('assistente');
  const [input,  setInput]  = useState('');
  const fimRef = useRef(null);

  const { historico, carregando, erro, totalTokens, enviar, limpar } = useChat({
    modelo:       'gpt-4o-mini',
    systemPrompt: SYSTEM_PROMPTS[modoSP],
  });

  useEffect(() => {
    fimRef.current?.scrollIntoView({ behavior: 'smooth' });
  }, [historico]);

  const handleEnviar = () => {
    enviar(input);
    setInput('');
  };

  return (
    <div className="chatbot">

      {/* Header com seletor de modo */}
      <header>
        <span>IA Assistant</span>
        <select value={modoSP} onChange={e => { setModoSP(e.target.value); limpar(); }}>
          <option value="assistente">🤖 Assistente</option>
          <option value="revisor">🔍 Revisor de Código</option>
          <option value="tutor">📚 Tutor Socrático</option>
        </select>
        <button onClick={limpar}>Nova conversa</button>
      </header>

      {/* Lista de mensagens */}
      <div className="mensagens">
        {historico.length === 0 && (
          <p className="vazio">
            Modo: {SYSTEM_PROMPTS[modoSP].slice(0, 60)}...
          </p>
        )}
        {historico.map((msg, i) => (
          <div
            key={i}
            className={`msg msg--${msg.role === 'user' ? 'user' : 'bot'}`}
          >
            {msg.content}
          </div>
        ))}
        {carregando && <div className="msg msg--typing">● ● ●</div>}
        {erro       && <div className="msg msg--error">❌ {erro}</div>}
        <div ref={fimRef} />
      </div>

      {/* Input + footer com tokens */}
      <div className="input-area">
        <input
          value={input}
          onChange={e => setInput(e.target.value)}
          onKeyDown={e => e.key === 'Enter' && handleEnviar()}
          disabled={carregando}
          placeholder="Mensagem..."
        />
        <button onClick={handleEnviar} disabled={carregando}>Enviar</button>
      </div>
      <footer>{totalTokens} tokens usados nesta sessão</footer>

    </div>
  );
}

Trocar de provedor sem mudar o componente

O ChatbotIA não sabe qual API está sendo chamada — ele só usa o hook useChat. Para trocar de provedor, basta criar uma nova versão do hook:

JSX — useChat adaptado para Gemini
import { GoogleGenerativeAI } from '@google/generative-ai';

const genAI = new GoogleGenerativeAI(import.meta.env.VITE_GEMINI_KEY);

export function useChatGemini({ systemPrompt } = {}) {
  const [historico,  setHistorico]  = useState([]);
  const [carregando, setCarregando] = useState(false);
  const [erro,       setErro]       = useState(null);

  const enviar = async (texto) => {
    setCarregando(true);
    const novoHistorico = [...historico, { role: 'user', content: texto }];
    setHistorico(novoHistorico);

    try {
      const model = genAI.getGenerativeModel({
        model: 'gemini-1.5-flash',
        systemInstruction: systemPrompt,
      });

      // Gemini usa formato diferente para o histórico
      const chat = model.startChat({
        history: novoHistorico.slice(0, -1).map(m => ({
          role:  m.role === 'assistant' ? 'model' : m.role,
          parts: [{ text: m.content }],
        })),
      });

      const result = await chat.sendMessage(texto);
      const resposta = result.response.text();

      setHistorico(h => [...h, { role: 'assistant', content: resposta }]);
    } catch (e) {
      setErro(e.message);
    } finally {
      setCarregando(false);
    }
  };

  return { historico, carregando, erro, enviar, limpar: () => setHistorico([]) };
}

6 Exercícios — APIs de IA, hooks e chatbot completo
Se não tiver chave de API, use a alternativa indicada para prática no material ou um mock local. O objetivo é exercitar a estrutura do hook, o histórico, os estados e a interface sem depender de gasto com API.
Como trabalhar esta atividade

Tente cada exercício antes de voltar aos exemplos das aulas. Use os blocos de código do conteúdo como referência conceitual, mas monte sua própria solução por etapas e teste a cada mudança.

  • Leia o enunciado e identifique quais estados, funções, componentes ou chamadas de API serão necessários.
  • Implemente uma parte por vez e valide no navegador antes de continuar.
  • Use o console e a aba Network do DevTools para investigar erros.
  • Não publique chaves de API em repositórios ou arquivos compartilhados.
  • Ao terminar, confira os critérios de conclusão de cada exercício.
Exercício 01

Implemente o hook useChat usando a Aula 1 como referência. Depois, crie um componente de teste mínimo com campo de texto, botão de envio e área de resposta. Faça pelo menos duas perguntas seguidas para verificar se o histórico está sendo preservado entre os turnos.

Básico — hook useChat
✓ Critérios para considerar concluído
  • Uma mensagem do usuário é adicionada ao histórico antes da chamada da API.
  • A resposta recebida aparece como mensagem do assistant.
  • Duas ou mais interações consecutivas permanecem visíveis no histórico.
  • O estado de carregamento impede envios duplicados enquanto a resposta não chega.
Exercício 02

Adicione ao hook useChat um parâmetro maxHistorico (padrão: 20 mensagens). Quando o histórico ultrapassar esse limite, remova as mensagens mais antigas — mantendo sempre o sistema de roles correto (sem remover o system prompt). Exiba no footer quantas mensagens foram truncadas.

Básico — gestão de contexto
✓ Critérios para considerar concluído
  • O limite padrão funciona com 20 mensagens e pode ser alterado por parâmetro.
  • Ao ultrapassar o limite, as mensagens mais antigas deixam de compor o histórico enviado.
  • O system prompt continua sendo enviado corretamente.
  • A interface informa quantas mensagens já foram descartadas/truncadas.
Exercício 03

Crie um componente SeletorSystemPrompt que permite ao usuário escolher entre 3 modos pré-definidos (Assistente, Revisor de Código, Tutor) e escrever um system prompt personalizado em um textarea. Ao trocar de modo, limpe o histórico automaticamente.

Básico — system prompt configurável
✓ Critérios para considerar concluído
  • Existem os modos Assistente, Revisor de Código e Tutor.
  • Há uma opção de prompt personalizado com textarea editável.
  • Trocar de modo atualiza o system prompt usado pelo chat.
  • Ao mudar o modo, a conversa anterior é limpa para evitar mistura de contextos.
Exercício 04

Implemente tratamento de erros visual completo no chatbot: erro 401 → "Chave inválida — verifique o .env"; erro 429 → "Limite atingido — aguarde X segundos" com countdown animado; erro de rede → "Sem conexão — verifique sua internet". Cada mensagem de erro deve ter um botão "Tentar novamente".

Médio — tratamento de erros por tipo
✓ Critérios para considerar concluído
  • Erros 401, 429 e falha de rede apresentam mensagens diferentes.
  • No 429, o usuário visualiza uma contagem regressiva antes de tentar novamente.
  • Existe uma ação de “Tentar novamente” quando ela fizer sentido.
  • O componente não deixa timers ou estados inconsistentes ao sair da tela.
Exercício 05

Integre o chatbot ao projeto multi-página da Semana 3: a página /chat deve estar protegida por React Router (requer API key no localStorage), o histórico deve ser salvo no HistoricoContext ao iniciar cada nova conversa, e a página /config deve permitir escolher o modelo (gpt-4o-mini ou gemini-1.5-flash).

Médio — integração Router + Context + API
✓ Critérios para considerar concluído
  • A rota /chat não é acessada quando a condição de proteção não é atendida.
  • A página /config altera o modelo usado pelo chat.
  • Uma nova conversa é registrada no HistoricoContext.
  • A integração continua funcionando após navegar entre as páginas do projeto.
Exercício 06 — Desafio

Monte o projeto final da P1: aplicação completa com (a) React Router com 3 páginas e rota protegida; (b) TemaContext (claro/escuro) e HistoricoContext persistido; (c) useChat conectado à API real ou Gemini gratuito; (d) system prompt configurável com 3 modos; (e) tratamento visual de todos os erros; (f) contador de tokens no footer; (g) botão "Nova conversa" que salva no histórico e limpa o chat.

Desafio — Projeto completo P1

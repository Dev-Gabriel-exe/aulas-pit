Por que dangerouslySetInnerHTML com IA é perigoso

A solução ingênua é converter o markdown para HTML com uma lib como marked e injetar com dangerouslySetInnerHTML. O problema: você está injetando HTML gerado por um modelo de linguagem externo diretamente no DOM.

Um LLM pode gerar — intencionalmente (jailbreak) ou acidentalmente — HTML com scripts embutidos. Se o conteúdo não for sanitizado, você tem uma vulnerabilidade XSS (Cross-Site Scripting) real que pode vazar dados do usuário, roubar cookies ou executar código arbitrário no browser de qualquer pessoa que use seu chatbot.

Nunca faça isso:
const html = marked(respostaIA);
<div dangerouslySetInnerHTML={{ __html: html }} />

Se o modelo retornar <script>document.cookie</script> como parte da resposta, ele será executado no browser do usuário.
A solução correta: react-markdown renderiza o markdown em componentes React — nunca em HTML cru. Por padrão, ele remove tags HTML perigosas do conteúdo. Você mantém total controle sobre quais elementos são renderizados e com qual CSS.
🙋 Por que react-markdown é mais seguro do que converter markdown para HTML e usar dangerouslySetInnerHTML?
A
react-markdown é mais rápido e consome menos memória do que soluções baseadas em HTML
B
react-markdown converte markdown em componentes React, não em HTML cru — scripts e tags perigosas no conteúdo da IA nunca chegam ao DOM como HTML executável
C
dangerouslySetInnerHTML foi depreciado no React 18 e não funciona mais
D
A diferença é apenas estética — ambas as abordagens têm o mesmo nível de segurança

react-markdown — instalação e uso básico

A biblioteca react-markdown converte uma string markdown em componentes React. A prop components permite sobrescrever como cada elemento markdown é renderizado — é aqui que você aplica seu próprio CSS e insere o highlight de código.

Terminal — instalação
npm install react-markdown remark-gfm react-syntax-highlighter
React — uso básico do react-markdown
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';

function MensagemIA({ conteudo }) {
  return (
    <ReactMarkdown
      remarkPlugins={[remarkGfm]}   // habilita tabelas, checklists, strikethrough
      className="markdown"           // classe CSS para estilizar globalmente
    >
      {conteudo}
    </ReactMarkdown>
  );
}
O que remark-gfm adiciona: GFM = GitHub Flavored Markdown. Sem ele, tabelas (| col |), listas de tarefa (- [x]), strikethrough (~~texto~~) e links automáticos não são renderizados. Como LLMs usam GFM com frequência, esse plugin é praticamente obrigatório.
react-syntax-highlighter — código colorido por linguagem

O react-markdown sozinho renderiza blocos de código como <pre><code> sem colorização. Para adicionar highlight, sobrescrevemos o componente code via a prop components e usamos o react-syntax-highlighter no lugar.

A lib detecta a linguagem a partir do marcador do bloco de código: ```python → language="python" na prop. Se não tiver marcador, cai para código inline simples.

React — componente MarkdownRenderer completo
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';
import { Prism as SyntaxHighlighter } from 'react-syntax-highlighter';
import { oneDark } from 'react-syntax-highlighter/dist/esm/styles/prism';
import { useState } from 'react';
import './MarkdownRenderer.css';

// Botão de copiar para blocos de código
function BotaoCopiar({ codigo }) {
  const [copiado, setCopiado] = useState(false);
  async function copiar() {
    await navigator.clipboard.writeText(codigo);
    setCopiado(true);
    setTimeout(() => setCopiado(false), 2000);
  }
  return (
    <button className="btn-copiar" onClick={copiar}>
      {copiado ? '✓ Copiado' : 'Copiar'}
    </button>
  );
}

// Componente personalizado para blocos de código
function BlocoCode({ node, inline, className, children, ...props }) {
  const match = /language-(\w+)/.exec(className || '');
  const linguagem = match ? match[1] : 'text';
  const codigo = String(children).replace(/\n$/, '');

  if (inline) {
    // código inline: `variavel` → estilizado mas sem highlight completo
    return <code className="code-inline" {...props}>{children}</code>;
  }

  return (
    <div className="bloco-codigo">
      <div className="bloco-codigo__header">
        <span className="bloco-codigo__lang">{linguagem}</span>
        <BotaoCopiar codigo={codigo} />
      </div>
      <SyntaxHighlighter
        style={oneDark}
        language={linguagem}
        PreTag="div"
        customStyle={{ margin: 0, borderRadius: '0 0 8px 8px', fontSize: '.82rem' }}
        {...props}
      >
        {codigo}
      </SyntaxHighlighter>
    </div>
  );
}

// Componente principal
export default function MarkdownRenderer({ conteudo }) {
  return (
    <ReactMarkdown
      remarkPlugins={[remarkGfm]}
      className="markdown"
      components={{ code: BlocoCode }}
    >
      {conteudo}
    </ReactMarkdown>
  );
}
Prism vs Highlight.js: react-syntax-highlighter oferece dois engines. Prism (importado como { Prism as SyntaxHighlighter }) tem melhor suporte para linguagens modernas como JSX, TypeScript e GraphQL. Highlight.js é mais leve. Para projetos com IA gerando código de múltiplas linguagens, prefira Prism.

Streaming + markdown — o desafio do markdown parcial

Combinar streaming (Semana 7) com markdown cria um desafio: durante a geração, o markdown está incompleto. Um bloco de código que ainda não fechou o ``` pode fazer o parser "engolir" o texto seguinte como código.

EstratégiaComo funcionaTrade-off
Renderizar diretoPassa respostaAtual para ReactMarkdown a cada tokenSimples. Pode ter artefatos visuais durante blocos de código incompletos
Renderizar só ao terminarExibe texto puro durante geração, ReactMarkdown só após [DONE]Elimina artefatos. Perde a sensação visual durante a escrita
Detectar blocos abertosConta ocorrências de ``` — se ímpar, não renderiza como markdown aindaMais complexo. Boa UX para respostas longas com código
Recomendação para o LAB: use a estratégia do meio — renderize texto puro durante o stream com uma fonte monospace para dar a sensação de digitação, e aplique o ReactMarkdown assim que gerando voltar para false. É o comportamento mais próximo do Claude e do ChatGPT.

Adicione abaixo de cada resposta da IA (após o markdown renderizado) um rodapé discreto mostrando: número de palavras na resposta e tempo de leitura estimado (palavras ÷ 200 ≈ minutos). function RodapeResposta({ texto }) {
  const palavras = texto.trim().split(/\s+/).filter(Boolean).length;
  const minutos = Math.max(1, Math.round(palavras / 200));

  return (
    <div style={{
      marginTop: '.65rem',
      paddingTop: '.5rem',
      borderTop: '1px solid rgba(255,255,255,.06)',
      fontSize: '.72rem',
      color: 'rgba(255,255,255,.3)',
      display: 'flex',
      gap: '1rem',
    }}>
      <span>{palavras} palavras</span>
      <span>{minutos} min de leitura</span>
    </div>
  );
}

Exercício 04 — Desafio: exportar conversa como Markdown

Adicione um botão "Exportar .md" que gera um arquivo Markdown com toda a conversa e faz o download automático no browser. Formato esperado:
# Conversa exportada\n\n## Você\n{mensagem}\n\n## IA\n{resposta}\n\n...
Use a API Blob e URL.createObjectURL para o download sem servidor.

Desafio
JavaScript — função exportarMarkdown
function exportarMarkdown(historico) {
  const data = new Date().toLocaleDateString('pt-BR');
  let md = `# Conversa exportada — ${data}\n\n`;

  historico.forEach(m => {
    const autor = m.role === 'user' ? '## Você' : '## IA';
    md += `${autor}\n\n${m.content}\n\n---\n\n`;
  });

  // cria o blob e dispara o download
  const blob = new Blob([md], { type: 'text/markdown;charset=utf-8' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = `conversa-${Date.now()}.md`;
  a.click();
  URL.revokeObjectURL(url);   // libera memória
}

// No JSX:
<button onClick={() => exportarMarkdown(historico)} disabled={historico.length === 0}>
  ⬇ Exportar .md
</button>

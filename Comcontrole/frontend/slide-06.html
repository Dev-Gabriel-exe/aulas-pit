Revisão rápida
Os 5 temas — pontos-chave e armadilhas comuns
Semana 1 — HTML/CSS/JS ES6+
HTML semântico: <header>, <main>, <section>, <article> — acessibilidade e SEO dependem disso
Flexbox: display:flex, justify-content, align-items, flex-wrap, gap
CSS Grid: grid-template-columns, fr, repeat(), auto-fill vs auto-fit
Variáveis CSS: --nome: valor; | var(--nome) — reutilização e temas
Arrow fn: const fn = (x) => x * 2 — this léxico (não cria próprio this)
Destructuring: const {nome, idade} = obj | const [a, b] = arr
Modules: import/export — organização e tree-shaking
Armadilha: var tem escopo de função, let e const têm escopo de bloco. const não é imutável — impede reatribuição, mas o objeto pode mudar.
Semana 2 — React Básico
Componente funcional: função JS que retorna JSX — começa com letra maiúscula
JSX: HTML dentro de JS. className em vez de class, htmlFor em vez de for
Props: dados que o pai passa para o filho — somente leitura no filho
useState: const [valor, setValor] = useState(inicial) — re-render ao mudar
Listas: array.map(item => <Li key={item.id}>) — key obrigatória e única
Condicional: condição && <Comp> | condição ? <A> : <B>
Eventos: onClick={fn} — não chame com () nas props (passa referência, não chama)
Armadilha: onClick={fn()} executa na renderização e passa o resultado como handler. Correto: onClick={fn} ou onClick={() => fn(args)}.
Semana 3 — React Avançado
useEffect: efeitos colaterais — chamadas de API, timers, listeners
Deps []: [] = roda uma vez | [valor] = roda quando valor muda | sem deps = todo render
Cleanup: return () => clearInterval(id) — evita memory leak em componentes desmontados
Lifting state: estado no pai, passado por props — fonte única de verdade
Context API: createContext → Provider → useContext — evita prop drilling
React Router: <BrowserRouter> → <Routes> → <Route path="/x" element={<X/>}>
useNavigate: navegar programaticamente; useParams: pegar :id da URL
Armadilha: fetch dentro de useEffect sem array de dependências cria loop infinito se o resultado atualizar um estado que é dependência.
Semana 4 — APIs REST
fetch básico: const res = await fetch(url); const data = await res.json();
POST com corpo: fetch(url, {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify(data)})
Tratamento de erro: if (!res.ok) throw new Error(res.status) — res.ok cobre 2xx
async/await vs then: await é açúcar sintático sobre Promise — mais legível
Axios: axios.get(url).then() — serializa body automaticamente, lança erro em 4xx/5xx
.env: REACT_APP_KEY=... no .env | process.env.REACT_APP_KEY no código — nunca commitar
States de loading: isLoading, error, data — os 3 estados de qualquer fetch
Armadilha: fetch não lança erro em 4xx/5xx — só em falha de rede. Cheque res.ok antes de chamar res.json().
Semana 5 — APIs de IA
OpenAI: POST /v1/chat/completions com model, messages (role + content)
HuggingFace: Inference API — POST com inputs no body, Authorization: Bearer TOKEN
Bearer token: Authorization: `Bearer ${process.env.REACT_APP_API_KEY}`
Rate limit (429): muitas requisições — exponential backoff ou fila local
Chave no front: NUNCA hardcodar — .env e, em prod, proxy no servidor
Contexto de mensagens: array de {role, content} para memória de conversa
temperature: 0 = determinístico, 1 = criativo — controla aleatoriedade
max_tokens: limite de tokens na resposta — cuidado com custo e truncamento
Armadilha: expor a chave da OpenAI no código front-end a torna visível no DevTools para qualquer usuário. Em produção, a chamada à API de IA deve passar por um servidor/proxy que injeta a chave. Na P1, citar isso é diferencial.

Estratégia para a parte prática
01
Leia o enunciado completo
Antes de escrever uma linha, entenda o que o componente precisa fazer. Identifique: quais dados ele exibe, o que dispara a busca, se há interação do usuário, quais estados são necessários.
02
Declare os estados primeiro
Antes de escrever o JSX, liste os useState necessários. Dado dinâmico de API → estado. Input do usuário → estado. Loading e erro → sempre. Dados derivados de estados → calcule na hora, não crie novo estado.
03
useEffect antes do return
Se o componente busca dados ao montar, escreva o useEffect com função async interna, try/catch/finally e array de deps [] após os estados. Não esqueça de verificar res.ok antes de chamar res.json().
04
JSX limpo e legível
Condicionais primeiro: if (carregando) return ... | if (erro) return ... — evita lógica dentro do JSX principal. Use componentes pequenos se o enunciado pedir. key={item.id} em toda lista.

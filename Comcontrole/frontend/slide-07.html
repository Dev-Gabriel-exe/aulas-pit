O problema da espera — e três formas de resolver
Por que streaming existe

Quando você faz uma pergunta a um LLM, o modelo não "pensa" a resposta completa e depois a envia. Ele gera um token de cada vez — cada token é uma palavra ou parte de palavra. Com uma resposta de 300 tokens a 30 tokens/segundo, você esperaria 10 segundos olhando para uma tela em branco.

Streaming resolve isso enviando cada token ao cliente assim que é gerado. A resposta começa a aparecer em milissegundos. O tempo total de geração é o mesmo, mas a latência percebida cai drasticamente. É a mesma diferença de assistir um vídeo em streaming vs baixar o arquivo completo antes de abrir.

Latência percebida vs latência real: um modelo que gera 300 tokens em 10s tem a mesma latência real com ou sem streaming. Mas com streaming, o usuário começa a ler na frente enquanto o modelo ainda gera o final. A experiência muda completamente.

SSE por dentro — o formato de evento

SSE usa uma conexão HTTP persistente. O servidor mantém a conexão aberta e envia eventos em texto puro com um formato específico. O cliente usa a API EventSource nativa do browser — sem bibliotecas.

Formato de evento SSE — o que chega no navegador
id:1
event:token
data:{"token": "Claro"}
id:2
event:token
data:{"token": ", aqui"}
id:3
event:token
data:{"token": " está"}
data:[DONE]
Cada bloco separado por linha em branco é um evento. data: [DONE] é a convenção da OpenAI para sinalizar fim do stream.
Formato obrigatório: cada campo termina com \n e cada evento termina com \n\n (linha em branco). O campo data: é o único obrigatório. Campos opcionais: id: (para replay), event: (tipo do evento), retry: (intervalo de reconexão em ms).

fetch com ReadableStream — lendo tokens da OpenAI
Por que não usar EventSource com a OpenAI

A API nativa EventSource do browser só faz requisições GET e não permite enviar cabeçalhos customizados como o Authorization: Bearer TOKEN. A API da OpenAI exige um POST com o body da requisição e o token de autenticação no header.

A solução é usar fetch com ReadableStream — a API fetch retorna um objeto Response que expõe response.body, um ReadableStream. Em vez de aguardar res.json() (que espera a resposta completa), lemos o stream em pedaços (chunks) à medida que chegam.

WebSocketCanal bidirecional persistenteNecessário quando o cliente também envia dados em tempo real durante a geração
ReadableStream — o fluxo de leitura

Quando o fetch retorna com stream: true, o corpo da resposta não é JSON — são linhas de texto SSE chegando incrementalmente. Cada linha começa com data: e contém um JSON com o delta do token. Precisamos de um TextDecoder para converter os bytes em texto.

JavaScript — lendo ReadableStream da OpenAI
async function streamOpenAI(mensagem, onToken, onFim) {
  const res = await fetch('https://api.openai.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.REACT_APP_OPENAI_KEY}`,
    },
    body: JSON.stringify({
      model: 'gpt-4o-mini',
      stream: true,              // ← ativa o streaming
      messages: [{ role: 'user', content: mensagem }],
    }),
  });

  if (!res.ok) throw new Error(`HTTP ${res.status}`);

  const reader = res.body.getReader();   // ReadableStreamDefaultReader
  const decoder = new TextDecoder();     // converte Uint8Array → string

  while (true) {
    const { done, value } = await reader.read();
    if (done) { onFim(); break; }

    const texto = decoder.decode(value, { stream: true });

    // cada chunk pode conter várias linhas SSE
    const linhas = texto.split('\n').filter(l => l.startsWith('data: '));

    for (const linha of linhas) {
      const payload = linha.slice(6);        // remove "data: "
      if (payload === '[DONE]') { onFim(); return; }

      try {
        const obj = JSON.parse(payload);
        const token = obj.choices[0]?.delta?.content ?? '';
        if (token) onToken(token);         // callback por token
      } catch { /* linha incompleta — ignorar */ }
    }
  }
}
Por que o try/catch dentro do loop? Um chunk pode chegar com uma linha SSE cortada no meio — o JSON incompleto falha no parse. Isso é normal: o próximo chunk trará o restante. Ignorar silenciosamente é a abordagem correta.
AbortController — cancelando o stream

O usuário clicou em "Parar" no meio da geração. Sem cancelamento, o fetch continua consumindo dados em background mesmo que você não precise mais deles. O AbortController resolve isso: um sinal que pode ser enviado ao fetch para abortar a requisição a qualquer momento.

React — AbortController com streaming

    const res = await fetch(url, {
      method: 'POST', headers, body,
      signal: abortRef.current.signal,   // ← conecta o controlador

    // ... ler o stream normalmente ...
  } catch (e) {
    if (e.name === 'AbortError') {
      console.log('Stream cancelado pelo usuário');

Por que useRef e não useState para o AbortController? O AbortController não é um dado que o componente exibe — é uma referência a um objeto externo. Colocá-lo em useState causaria um re-render toda vez que fosse criado. useRef persiste entre renders sem causá-los.
🙋 Por que usar useRef para armazenar o AbortController em vez de useState?
A
useState não consegue armazenar objetos — só primitivos como strings e números
B
useRef persiste o valor entre renders sem disparar um novo render — ideal para referências imperativas que não precisam ser exibidas
C
AbortController só funciona dentro de refs — é uma limitação da API do browser
D
useState é assíncrono — o AbortController precisa ser criado sincronicamente

React — ChatbotStream.jsx completo
import { useState, useRef, useEffect } from 'react';
import './ChatbotStream.css';

export default function ChatbotStream() {
  const [historico, setHistorico] = useState([]);
  const [input, setInput] = useState('');
  const [gerando, setGerando] = useState(false);
  const [respostaAtual, setRespostaAtual] = useState('');
  const abortRef = useRef(null);
  const endRef = useRef(null);

  // auto-scroll quando novos tokens chegam
  useEffect(() => {
    endRef.current?.scrollIntoView({ behavior: 'smooth' });
  }, [respostaAtual, historico]);

  async function enviar() {
    if (!input.trim() || gerando) return;

    const novaMensagem = { role: 'user', content: input };
    const novoHistorico = [...historico, novaMensagem];
    setHistorico(novoHistorico);
    setInput('');
    setRespostaAtual('');
    setGerando(true);

    abortRef.current = new AbortController();

    try {
      const res = await fetch('https://api.openai.com/v1/chat/completions', {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'Authorization': `Bearer ${process.env.REACT_APP_OPENAI_KEY}`,
        },
        body: JSON.stringify({
          model: 'gpt-4o-mini',
          stream: true,
          messages: novoHistorico,
        }),
        signal: abortRef.current.signal,
      });

      if (!res.ok) throw new Error(`HTTP ${res.status}`);

      const reader = res.body.getReader();
      const decoder = new TextDecoder();
      let textoCompleto = '';

      while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        const chunk = decoder.decode(value, { stream: true });
        const linhas = chunk.split('\n').filter(l => l.startsWith('data: '));

        for (const linha of linhas) {
          const payload = linha.slice(6);
          if (payload === '[DONE]') break;
          try {
            const token = JSON.parse(payload).choices[0]?.delta?.content ?? '';
            if (token) {
              textoCompleto += token;
              setRespostaAtual(textoCompleto);
            }
          } catch {}
        }
      }

      // adiciona resposta completa ao histórico
      setHistorico(prev => [...prev, { role: 'assistant', content: textoCompleto }]);

    } catch (e) {
      if (e.name !== 'AbortError') {
        setHistorico(prev => [...prev, { role: 'assistant', content: 'Erro ao gerar resposta.' }]);
      }
    } finally {
      setGerando(false);
      setRespostaAtual('');
    }
  }

  function parar() {
    abortRef.current?.abort();
  }

  return (
    <div className="chat">
      <div className="chat__mensagens">
        {historico.map((m, i) => (
          <div key={i} className={`bubble bubble--${m.role}`}>
            <span className="bubble__label">{m.role === 'user' ? 'Você' : 'IA'}</span>
            {m.content}
          </div>
        ))}
        {gerando && respostaAtual && (
          <div className="bubble bubble--assistant">
            <span className="bubble__label">IA · gerando...</span>
            {respostaAtual}
            <span className="cursor"></span>
          </div>
        )}
        <div ref={endRef} />
      </div>

      <div className="chat__input-area">
        <textarea
          value={input}
          onChange={e => setInput(e.target.value)}
          onKeyDown={e => e.key === 'Enter' && !e.shiftKey && (enviar(), e.preventDefault())}
          placeholder="Digite sua mensagem... (Enter para enviar)"
          disabled={gerando}
        />
        <div className="chat__buttons">
          <button onClick={enviar} disabled={gerando || !input.trim()}>Enviar</button>
          {gerando && <button onClick={parar} className="btn-parar">⏹ Parar</button>}
        </div>
      </div>
    </div>
  );
}

Exercício 01 — Entendendo o chunk

Adicione um console.log(chunk) dentro do loop de leitura do stream e observe o output no DevTools. Responda: (a) cada chunk corresponde a exatamente um token? (b) o que acontece quando uma linha SSE chega cortada no meio de um chunk? Como o código atual lida com isso?

Conceito + observação
  • (a) Não — um chunk pode conter zero, um ou vários tokens. O tamanho do chunk depende da velocidade da rede e do buffer do servidor. Em condições rápidas, um único chunk pode trazer 5–10 linhas SSE de uma vez.
  • (b) Quando a linha SSE é cortada no meio, JSON.parse(payload) falha com SyntaxError. O try/catch captura o erro silenciosamente e passa para o próximo chunk. O próximo chunk trará a continuação da linha — mas como cada chunk é processado de forma independente, o fragmento anterior é descartado. Para casos críticos, a solução robusta é um buffer acumulador que junta fragmentos entre chunks antes de tentar o parse.
Exercício 02 — Indicador de tokens por segundo

Adicione ao chatbot um contador que mostra a velocidade do stream em tempo real: "X tokens/s". Use um useRef para guardar o timestamp do início da geração e o total de tokens recebidos. Atualize o display a cada token com useState. Some o estado de geração para exibir "— tokens/s" quando não está gerando.

Exercício 04 — Desafio: fake stream sem API key

Crie uma função fakeStream(texto, onToken, onFim) que simula o streaming palavra a palavra, com intervalo de 80ms entre tokens, usando setTimeout e AbortController para cancelamento. Use para testar toda a interface do chatbot sem precisar de chave de API. A função deve respeitar o sinal de abort e parar a geração imediatamente quando acionado.

Desafio
JavaScript — fakeStream.js
export function fakeStream(texto, onToken, onFim, signal) {
  const tokens = texto.split(' ');  // divide em palavras
  let i = 0;
  let timeoutId;

  function enviarProximo() {
    if (signal?.aborted || i >= tokens.length) {
      onFim();
      return;
    }
    // adiciona espaço antes de cada palavra (exceto a primeira)
    onToken(i === 0 ? tokens[i] : ' ' + tokens[i]);
    i++;
    timeoutId = setTimeout(enviarProximo, 80);
  }

  // para imediatamente se o abort já foi acionado
  signal?.addEventListener('abort', () => {
    clearTimeout(timeoutId);
    onFim();
  });

  enviarProximo();
}

O que você precisa ter saído daqui dominando
SSE vs WebSocket

SSE: unidirecional, HTTP puro, reconexão automática — ideal para stream de IA. WebSocket: bidirecional, full-duplex — para chat ao vivo e colaboração.

ReadableStream + TextDecoder

fetch retorna response.body como stream. getReader().read() lê chunks. TextDecoder converte bytes em texto. Filtrar linhas data: e ignorar [DONE].

AbortController + useRef

AbortController cancela o fetch. Fica em useRef (não useState) para não causar re-renders. Verificar e.name === 'AbortError' para distinguir de outros erros.
